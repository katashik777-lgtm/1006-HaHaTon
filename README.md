## 1. Описание решения

Скорифай сравнивает ответы двух версий стратегии по одним и тем же кредитным заявкам. Аналитик видит, сколько решений поменялось, какие поля изменились вместе с ними и какие исходные ответы подтверждают наблюдение. Из числа на экране можно перейти в список заявок, затем открыть конкретную заявку и сравнить поля и документы до и после изменений.

- **Простой режим** показывает доли одобрений и отказов, переходы решений, качество данных и готовые отчёты. Он открывается по умолчанию.
- **Расширенный режим** добавляет сводную с изменяемой раскладкой, общие фильтры, скоркарты, проверки Python, сравнение сценариев и журнал обработки.
- **Конструктор** сохраняет выбор набора, профиля, процедур и проверок. Код можно написать в редакторе или загрузить из файла `.py`. Готовый прогон сохраняет снимок кода и параметров.
- **Отчёты** доступны в HTML, Excel и XML. Сводная выгружает факты в CSV и JSON. Отчёт проверок имеет свою ссылку и отдельную выгрузку HTML.
- **Работа в команде** поддерживает личные аккаунты, роли проектов, отдельные конфигурации и журнал действий. Обработка идёт в фоне, пока пользователи работают с уже опубликованными отчётами.

## 4. Данные

Основной источник — открытый набор организаторов `RUN-20260827-0001` в папке `ПАКЕТ/ЗАДАНИЕ/data/`. Это **2 002 заявки и 4 004 JSON-файла**, по одному ответу на заявку в каждом срезе.

- **До изменений** — `BEFORE_MASTER`, базовая версия стратегии.
- **После изменений** — `AFTER_BETA`, версия с правками.

Приложение сверяет ID из имени файла и документа, проверяет структуру, отмечает дубликаты и отсутствующие ответы. Технические поля исключаются согласно профилю. Для основного сравнения используются пары с корректными ответами в обеих версиях. Неполные пары видны в отчёте качества.

Учебные примеры и сгенерированные ответы используются в тестах форматов и граничных случаев. Дополнительные внешние источники в итоговый прогон не включались. Для повторной сверки используется SHA-256 отсортированных ID из открытого эталона. Он хранится отдельно от исходных ответов и не участвует в расчёте.

## 5. Архитектура и подход

1. **Импорт.** API принимает JSON, XML и CSV, сохраняет исходные файлы и контрольные суммы. Конфигурация прогона фиксируется перед постановкой задания в очередь.
2. **Нормализация.** Профиль задаёт типы, исключения и правила массивов. Оба среза объединяются вертикально с признаком версии `SOURCE`.
3. **Сопоставление.** Строки сравниваются по заявке, пути поля и каноническому ключу элемента массива. Порядок элементов учитывается только в массивах, для которых он имеет смысл. Категории чисел используются в группировках, а сравнение использует исходные значения.
4. **Витрина и проверки.** Worker формирует Parquet и индексированную таблицу различий. Выбранные процедуры выполняются на зафиксированных входах. Итоги `PASS` и `FAIL`, ошибки исполнения и статистика бакетов хранятся отдельно.
5. **Публикация.** После проверки артефактов результат открывается по постоянной ссылке. DuckDB читает витрину. Сводная считает уникальные ID внутри группы, а детализация использует те же условия. Один ID может входить в несколько групп.
6. **Долгие операции.** Worker обновляет этап и прогресс, пока API продолжает обслуживать интерфейс. Журнал хранит время, детали и код ключевых этапов. Задание можно отменить или повторить. Перезагрузка браузера восстанавливает страницу прогона по URL.

**Что проверили на экспериментах**

- При перестановке элементов массива сравнение по ключу сохраняет правильные пары. Учебные примеры проверяют это отдельно от сравнения по индексу.
- Если число изменилось внутри того же диапазона, сводная сохраняет категорию, а сравнение отмечает изменение исходного значения. Это проверено на эквивалентных JSON, XML и CSV.
- Счётчик сводной и список заявок согласованы. На полном наборе проверены все 20 групп разреза «продукт × версия × признак изменения».
- В контрольном запуске чтение и нормализация заняли 3,09 с из 5,33 с. Это самый длительный этап на выданном наборе.
- На Railway сравнение большого набора разбито на партии по 200 заявок, чтобы ограничить размер промежуточных таблиц. Принадлежность заявки к одной партии сохраняет корректный подсчёт уникальных ID.

## 7. Инструкция по запуску

### Онлайн-демо

Откройте [Скорифай на Railway](https://scorify-production.up.railway.app) и нажмите **Открыть готовый демоотчёт**. Для демонстрации конструктора и журнала войдите через обычную форму с логином и паролем `admin`.

### Локально на чистом компьютере

Нужен Python **3.12–3.14** с pip. Интернет нужен при первой установке зависимостей. Скачайте весь репозиторий вместе с учебными материалами. Готовый интерфейс включён.

Для получения копии через Git выполните:

```bash
git clone --depth 1 https://github.com/katashik777-lgtm/1006-HaHaTon.git
cd 1006-HaHaTon
```

- **Windows** — откройте `install-local.cmd`, затем `start-local.cmd`.
- **macOS** — откройте `install-local.command`, затем `start-local.command`.
- **Linux или терминал macOS** — выполните команды из корня проекта.

```bash
python3 launch.py install --local-demo
python3 launch.py start
```

В терминале Windows используйте `py -3` вместо `python3`. Установка создаёт окружение `.venv/`, применяет миграции и загружает оба среза открытого набора. Запуск поднимает API и обработчик. Откройте [локальный Скорифай](http://127.0.0.1:8765), войдите с логином и паролем `admin`. Остановка — **Ctrl+C** в терминале запуска.

Для повторения полного отчёта в браузере откройте **Расширенный → Конструктор**. Выберите **Открытый набор · 2002 заявки**, профиль `main`, нажмите **Выбрать все** для пяти проверок и **Запустить обработку**. Ход работы виден в журнале. После завершения откройте **Обзор**, **Сводную таблицу** или **Проверки**.

```bash
python3 launch.py test
.venv/bin/python scripts/acceptance.py
```

В Windows используйте `py -3 launch.py test` и `.venv\Scripts\python scripts/acceptance.py`. Скрипт использует доверенный локальный Python для комплектных проверок.

## 8. Ограничения

- Сценарный расчёт оценивает влияние балла, порога и стоп-факторов. Полная стратегия СПР и причинность изменений требуют проверки по исходной стратегии. Реальное исполнение двух версий через HTTP требует адресов и согласованного формата ответа.
- В пользовательском CSV один файл представляет один ответ. Для дополнительных схем нужны правила приведения в профиле.
- Комплектная проверка может вернуть только примеры заявок из полной группы. Отчёт показывает общее число и отдельно тот список ID, который вернула проверка.
- Локальные пользовательские процедуры запускаются в доверенном режиме. На Railway для них используются ограничения ОС. На производительность влияет объём входа и код выбранных процедур.
- Текущие замеры описывают конкретный открытый набор. Дальнейшая работа — испытания больших реальных выгрузок, измерение пика памяти и нагрузочное тестирование одновременных пользователей.
- Перезагрузка восстанавливает прогон, вкладку и параметры сводной, сохранённые в URL. Незавершённые правки редактора и общие фильтры обзора остаются состоянием текущей страницы.
