# Требования к понятному интерфейсу

Основание: https://habr.com/ru/articles/872168/ (прочитано 07.11.2026).

| Принцип | Реализация в проекте | Критерий проверки |
|---|---|---|
| Ориентация на пользователя | Разделы и действия учитывают роль; пояснения описывают следующий шаг | Наблюдателю не предлагается загрузка данных |
| Простота, Хик | Навигация: анализ, подготовка, управление; процедуры скрыты в дополнительных настройках | Обычный запуск не требует просмотра кода процедур |
| Последовательность | Общие стили кнопок, фокуса, уведомлений и таблиц | Одинаковые действия имеют одинаковое поведение |
| Обратная связь | Ошибки и успех объявляются через alert/status; регистрация показывает ожидание | Создание аккаунта отображается как успех |
| Эффективность | Сохранённые настройки сохранены; строки открываются кнопками с клавиатуры | Enter открывает детализацию |
| Фиттс | Основные элементы управления высотой от 44 px | Кнопки доступны на узком экране |
| Миллер | Общие таблицы показывают по 10 строк | Остальные строки доступны через пагинацию |
| Близость | Связанные настройки, сообщения и поля сгруппированы | Подсказка пароля находится непосредственно под полем |
| Якоб | Подписанные меню, стандартные формы, показ пароля, Назад/Далее | Назначение элементов понятно без знания иконок |
| Когнитивная нагрузка | Обзор начинается с маршрута и KPI; разрезы влияния раскрываются отдельно | Детали доступны по запросу |
| Постел | Логин очищается от крайних пробелов; пароль сохраняется без преобразований | Вставка работает; кириллица вызывает объяснение, а не молчаливое удаление |

## Пароли

При создании пароля запрещена кириллица, в том числе ё/Ё и смешанный ввод. Ограничение действует в форме и в общем серверном hash_password, включая создание пользователей через API и CLI. Минимум остаётся 12 символов. Проверка не пытается определять активную раскладку ОС: проверяется фактический текст. Пароль не обрезается и не транслитерируется. Старые пароли продолжают проверяться без нового ограничения.

## Проверка сценариев

- Регистрация: короткий пароль блокируется; кириллица при наборе или вставке блокирует отправку и даёт подсказку; исправление позволяет отправить форму.
- Вход: поддерживаются менеджер паролей, показ/скрытие и старые пароли.
- Аналитик: данные → конструктор → запуск → обзор → заявки → исходные поля.
- Наблюдатель: просмотр результатов без предложения редактирования.
- Таблицы: доступны все строки; изменение данных возвращает первую страницу.
- Адаптивность: подписи навигации видны на узком экране; фокус виден с клавиатуры; анимации отключаются при prefers-reduced-motion.

Рабочий интерфейс служит проверяемым прототипом. Проверки с реальными аналитиками и согласование с заказчиком требуют их участия; автоматические проверки их не заменяют. Офлайн-режим и банковские сценарии в статье — примеры требований, а не требования к этому проекту.
