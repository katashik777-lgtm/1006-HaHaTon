# Контракты процедур

Конструктор поддерживает parse, normalize, compare, facts, check. Преобразования используют run(data, params).

parse получает text, format, profile, app_id, source и возвращает объект общей модели. Контракты нормализации и сравнения приведены ниже. facts преобразует membership; counts рассчитываются системой по уникальным APP_ID, чтобы сохранить связь с детализацией.

Пробное выполнение использует первые 100 строк завершённого прогона; вход разбора задаётся JSON в редакторе. Доступны результат, stdout, stderr, traceback. Диагностика сохраняется в procedure-diagnostics.jsonl. Выбор процедур и их код сохраняются в снимке запуска. Журнал пользовательских этапов позволяет раскрыть исполненный код.

Разбор запускает отдельный процесс для каждого документа и требует оптимизации для больших наборов. На Windows требуется доверенный локальный режим.


## Обновлённые контракты замены
normalize получает {document, app_id, source, profile}, возвращает строки схемы normalize.COLS. compare получает {rows, valid_ids, profile}, возвращает строки схемы сравнения. Эти процедуры полностью заменяют встроенный обработчик. Примеры создаются выбором типа в редакторе. facts работает с membership и сохраняет связь counts с APP_ID.
Редактор сохраняет порядок ячеек и результаты. Ячейки одного редактора выполняются в общем Python-сеансе. Чтобы начать с чистого состояния, нажмите «Сбросить сеанс». На Railway проверки читают материалы выбранного прогона, а сеанс ячеек работает со своими переменными и временными файлами. Сеть и база приложения из Python недоступны.

Снимок прогона хранит результаты `PASS` и `FAIL` в `checks.json`. `CNT` и `TOTAL` в проверках относятся к заявкам. Распределения и переходы находятся в `buckets.json` и считают строки атрибутов. Ошибки исполнения находятся в `check_errors.json`. В XML этим данным соответствуют разделы `checks`, `statistics` и `checkErrors`.
