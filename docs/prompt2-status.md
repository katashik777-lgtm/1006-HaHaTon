# Выполнение задания по сравнению заявок

Общая выборка применяется к обзору, сводной, качеству, проверкам, скоркартам, сценариям и расшифровкам. Сервер применяет фильтры к полной выборке до агрегации и пагинации. Исторический режим использует решения из ответов. Сценарный пересчитывает решения и бакеты Score поверх опубликованного снимка. Контракт сырых значений и признаков изменения сохранён.

- `spr/analysis_scope.py` задаёт правила отбора, расчёт сценария и проекции над сохранённой витриной. `spr/api.py` использует выборку в отчётах, расшифровках и экспорте сводной. `spr/pipeline.py` сохраняет данные односторонних заявок отдельно от валидных пар.
- `frontend/src/DecisionAnalysis.tsx` содержит общие фильтры, матрицу, постраничную продуктовую аналитику и скоркарту заявки. Отчёт о проверках показывает распределения и переходы. Качество показывает состав ошибок по каждому срезу и раскрывает затронутые заявки.
- Импорт одной партии файлов записывает метаданные одной транзакцией. Ошибка в партии оставляет её вне реестра импорта. Повторное сравнение работает по снимку списка файлов прогона. Тесты также проверяют отмену, повторный запуск и восстановление опубликованного снимка.

## Воспроизведение в браузере

Используйте отдельную локальную рабочую область. Сценарий создаёт датасеты, обновляет профиль `main` и запускает проверки через интерфейс. На macOS или Linux после установки зависимостей:

```sh
export SPR_DATA="$(mktemp -d)"
.venv/bin/python -m spr.cli local-reset
python3 launch.py start
```

Во втором терминале установите Playwright и запустите браузерную проверку. По умолчанию используется Chrome и локальный демонстрационный вход. При необходимости задайте `BROWSER_CHANNEL` или укажите файл с тестовым логином и паролем через `SPR_TEST_CREDENTIALS`.

```sh
npm --prefix frontend ci
npm --prefix frontend run build
npm install --prefix /tmp/scorify-browser playwright
export PLAYWRIGHT_MODULE=/tmp/scorify-browser/node_modules/playwright
export SPR_BROWSER_OPEN_DATASET="$(printf '%s' "$PWD"/ХАК*/ПАКЕТ/ЗАДАНИЕ/data/RUN-20260827-0001)"
node scripts/browser-prompt2.cjs
```

Сценарий загружает файлы в обычную форму, запускает фоновую обработку и проверяет опубликованные отчёты. Эталонные JSON, XML и CSV с `;` и `,` дают одинаковые сравнения, продуктовые записи и бакеты. Проверка чистого набора показывает ноль нарушений. После добавления повреждённого JSON проверка раскрывает ошибку разбора до файла. Проверены ANY/ALL, одновременное действие фильтров, строгая и нестрогая граница порога, расчёт обоих режимов, матрица, причины, расшифровка сводной, распределения и перехода, повторный запуск сохранённых проверок Python для текущей выборки.

При заданном `SPR_BROWSER_OPEN_DATASET` сценарий дополнительно загружает через ту же форму 4 004 комплектных ответа. Проверка ожидает 2 002 валидные пары и 289 533 строки сравнения. Без переменной выполняются эталонные и диагностические проверки.

## Границы расчётной модели

Исходные данные содержат Score, пороги, срабатывания правил и исторические решения. Поставленных бизнес-настроек штрафов, списка обязательных факторов и полного расчёта вкладов признаков нет. В жёстком сценарии все сработавшие факторы считаются обязательными, пока профиль не перечислит их явно. Значения штрафа и направление сравнения задаются в профиле или фильтрах. Сценарный результат заявки сводится из продуктов по правилу «любое одобрение». Историческое решение сохраняется отдельно.

Для уже опубликованного прогона без сохранённых результатов по односторонним заявкам их наличие определяется реестром качества. Для детализации их продуктовых решений нужен новый прогон. Проверки Python используют интерфейс витрины с отбором валидных пар. Их собственные правила группировки и ограничения примеров остаются частью кода проверки. Внешняя СПР и фактические банковские штрафы не проверялись.
