# Расхождения источников

1. examples/README.md: пять изменений; CSV 06 показывает **шесть**: decision, riskSegment, TAKEUP_RATE_IP.value/version, limit, DOCS_EXPIRED. Проверяется содержимое CSV.
2. README: 440 заявок. Факты решения дают **465 на срез** с обоими DIFF_FLAG. 59 фактов — отдельный демонстрационный набор; APP_ID отсутствуют, переход к заявкам невозможен.
3. example: KEY=code для скалярных причин; examples: KEY пустой. Это отдельные профили учебных представлений.
4. 06: PATH/CHANGE_TYPE или COMMENT — варианты диагностики, не изменение MartAPI.
5. Ранний план обещает готовые процедуры и потоковую обработку; подробная карточка требует реализации процедур, последнее уточнение допускает публикацию только завершённого отчёта.
6. Выданная external_score_drift называет корреляцию причиной и перезаписывает значения предикторов разных моделей в словаре по APP_ID. Исполняем исходник без изменений; в UI помечаем как наблюдение, требующее проверки по моделям.
7. Выданная stop_factor_disappeared разбирает ARRAY_KEY по |. Канонические ключи используют JSON; адаптер MartAPI предоставляет совместимую экранированную проекцию, сохраняя канонический ключ отдельно.
8. Схема сегментов требует одну строку на заявку, а модели и пороги могут различаться по продуктам. Приоритет у продукта, явно указанного в ответе по пути `decision_product_path`. Иначе используется единственный продукт с решением, совпадающим с итогом заявки. При неоднозначности поля сегмента остаются пустыми, продуктовые строки доступны отдельно. Совпадение решений само по себе не устанавливает причинность.
