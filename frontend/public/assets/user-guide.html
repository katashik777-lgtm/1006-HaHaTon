1. Что делает приложение

Скорифай сравнивает две версии ответов системы принятия решений (СПР). Он показывает, что изменилось в заявках, какие решения сменились и какие поля связаны с этими изменениями.

ТерминЗначение
BEFORE / MASTER / «До»Исходная версия ответа
AFTER / BETA / «После»Новая версия ответа
APP_IDИдентификатор заявки; это не обязательно идентификатор человека
ДатасетНабор файлов двух версий
Профиль общей моделиПравила чтения, типов, сопоставления массивов и бакетов
ПрогонОтдельный запуск обработки датасета с выбранным профилем и проверками
Валидная параЗаявка, для которой обе версии пригодны для сравнения
АтрибутОтдельное поле ответа, например значение Score
БакетИнтервал чисел или строковая категория
Стоп-факторСработавшее правило, влияющее на возможность одобрения
Историческое решениеРешение из загруженного ответа СПР
Расчёт сценарияРезультат упрощённого моделирования в приложении

Изменение атрибута не обязательно меняет решение. Совпадение изменений двух полей не доказывает причинную связь. Для проверки вывода открывайте соответствующие заявки и исходные документы.

2. Запуск и вход

Если приложение уже установлено

  • Откройте терминал в папке проекта.
  • Выполните python launch.py start.
  • Откройте локальный сайт.
  • Оставьте терминал работающим. Для остановки нажмите в нём Ctrl+C.

Для онлайн-демо откройте Скорифай и нажмите «Открыть готовый демоотчёт». Чтобы снова обработать открытые данные, нажмите «Повторить демосравнение». Для загрузки своих файлов нужен личный аккаунт с ролью аналитика. Если открыто демо, нажмите «Войти в свой аккаунт». Для входа администратором на сервере и на своём компьютере введите admin в оба поля.

Первичная установка на Windows и macOS

  • Windows. Установите Python, откройте install-local.cmd, затем start-local.cmd.
  • macOS. Установите Python, откройте install-local.command, затем start-local.command.

Локальная установка настраивает вход администратора admin / admin. Параметр --local-demo добавляет открытый учебный набор.

Вход и регистрация

  • Введите имя пользователя и пароль.
  • Кнопка «Показать» позволяет проверить введённый пароль.
  • Нажмите «Войти».

Если аккаунта нет, нажмите «Создать аккаунт». Новый пароль должен содержать не менее 12 символов и не содержать кириллицу. При ошибке раскладки исправьте буквы вручную: приложение не меняет пароль автоматически.

После регистрации доступ к проекту назначает администратор. Сообщение «Аккаунт создан» не означает, что доступ уже выдан.

Роли

  • Наблюдатель изучает доступные результаты.
  • Аналитик работает с данными и запускает анализ в пределах выданных прав.
  • Ведущий аналитик получает расширенные инструменты, включая работу с процедурами и журналом.
  • Администратор управляет пользователями и доступом.

Если нужный раздел или кнопка отсутствует, проверьте выбранный проект и роль. Недоступная кнопка также может означать, что ещё не выбраны данные или не завершён прогон.

3. Первый анализ за десять шагов

  • Выберите проект в левой панели.
  • Откройте «Данные и профили».
  • Создайте датасет с понятным названием, например «Стратегия 07.11 — сравнение».
  • Выберите срез BEFORE и загрузите исходные файлы.
  • Выберите AFTER и загрузите новые файлы в тот же датасет.
  • Проверьте профиль общей модели; для комплектных данных используется main.
  • Откройте «Конструктор», выберите датасет, профиль и проверки.
  • Нажмите «Запустить обработку» и дождитесь статуса «Готово».
  • Сначала изучите «Качество данных», затем «Обзор» и «Проверки».
  • Откройте число в отчёте, выберите заявку, сравните поля и исходные документы.

При выборе другого прогона убедитесь, что дата, датасет и статус соответствуют нужному анализу. Настройки профиля сохраняются в снимке запуска: изменение профиля не пересчитывает готовый отчёт.

4. Подготовка и загрузка файлов

Общие требования

Один файл соответствует одной заявке. По умолчанию имя файла без расширения должно совпадать с ID внутри документа. Например, I32554358.json соответствует заявке I32554358. Путь к внутреннему ID задаётся профилем.

Для одной заявки подготовьте файл BEFORE и файл AFTER. Файлы могут иметь одинаковое имя, потому что загружаются в разные срезы.

Не загружайте повторно тот же ID в один срез для замены данных: он может быть отмечен как дубликат. Для исправленного набора создайте новый датасет. Отсутствующий ответ одной версии отражается в качестве данных и не считается обычным исчезнувшим атрибутом валидной пары.

JSON

Поддерживаются объекты и вложенные структуры. Массивы сопоставляются по правилам профиля: по ключу, значению либо позиции.

{
  "appData": {"application_id": "I100"},
  "decisionResult": {"decision": "APPROVE"},
  "score": 0.637
}

Это минимальный пример чтения полей, а не полный контракт продуктовой скоркарты. Для появления Score в продуктовой аналитике структура должна соответствовать путям профиля и ожидаемой структуре продукта.

XML

XML разбирается с учётом вложенности и повторяющихся элементов. Атрибуты XML представлены ключами с префиксом @. Обработка пространств имён зависит от профиля.

Текст 0.637 в XML не становится числом сам по себе: задайте соответствующий тип поля в профиле. Также задайте типы булевых полей стоп-факторов. Структура одиночных и повторяющихся XML-элементов должна соответствовать правилам массивов выбранного профиля.

CSV

Текущий импорт ожидает одну строку данных на файл, плюс строку заголовков. Многострочный CSV со всеми заявками сразу не является текущим контрактом импорта.

Разделитель по умолчанию — ;. Другой разделитель задаётся через delimiter профиля. Вложенные объекты и массивы можно передавать JSON-строкой в ячейке. Поля с разделителем, кавычками или переносом строки необходимо корректно заключать в кавычки по правилам CSV.

Простой пример:

appData.application_id;decisionResult.decision;score
I100;APPROVE;0.637

Для этого примера задайте types: {"score": "number"}. Десятичный разделитель числового значения — точка. Строковый код 0012 не объявляйте числом, если ведущие нули имеют значение.

Порядок загрузки

  • Введите название датасета и нажмите «Создать датасет».
  • Убедитесь, что он выбран в списке «Датасет».
  • В поле «Срез» выберите BEFORE / MASTER.
  • Нажмите «Выбрать файлы ответов», выберите все исходные файлы.
  • Дождитесь сообщения о сохранённых ответах.
  • Переключите срез на AFTER / BETA и повторите загрузку новых файлов.
  • Нажмите «Перейти к обработке».

Сообщение о сохранении файлов подтверждает загрузку. Проверка структуры и пригодности для сравнения выполняется во время обработки.

5. Профиль общей модели и бакеты

Профиль редактируется в разделе «Данные и профили» в виде JSON. Перед изменением сохраните копию текущего текста, чтобы можно было восстановить настройки.

Основные настройки:

НастройкаЧто определяет
app_idПуть к ID заявки
requiredОбязательные поля
typesЯвные типы полей, включая поля вложенных массивов
arraysКак сопоставлять элементы массивов
excludeКакие поля исключить из сравнения
delimiterРазделитель CSV
bucket_widthОбщий шаг числовых бакетов
bucket_configШаг и зона порога конкретного атрибута
bucketsЯвные интервалы для конкретного атрибута
numeric_toleranceДопустимая разница при сравнении чисел

Пример настройки бакетов

Ниже фрагмент для добавления в существующий профиль. Не заменяйте им весь профиль: в нём могут быть необходимые правила ID и массивов.

{
  "bucket_version": 2,
  "bucket_width": 0.2,
  "bucket_config": {
    "decisionResult.product_trials.scoring.pd.value": {
      "width": 0.2,
      "threshold": 0.6,
      "radius": 0.1,
      "scale_min": 0,
      "scale_max": 1
    }
  }
}

threshold здесь — опорная граница бакетизации атрибута. Она задаётся явно и не подставляется автоматически из порога каждого продукта. Обе версии используют одну конфигурацию.

Интервал (0.5 – 0.6] означает: значение больше 0.5 и меньше либо равно 0.6. Число 0.6001 уже не входит в этот интервал. Строковые атрибуты остаются категориями.

На шкале 0..100 вместо шага 0.2 обычно нужен шаг 20, а вместо радиуса 0.1 — радиус 10. Единицы задавайте в соответствии с полем, а не по его названию.

После изменения нажмите «Сохранить профиль» и создайте новый прогон. Готовые отчёты продолжают использовать свой снимок настроек.

Изменение значения и изменение бакета — разные вещи

При интервале (0.3 – 0.6] значения 0.42 и 0.58 находятся в одном бакете. Изменение 0.42 → 0.58 всё равно остаётся VALUE_CHANGED. Оно будет видно в сравнении полей, но не попадёт в список переходов между разными бакетами.

6. Запуск обработки

В «Конструкторе»:

  • Выберите датасет.
  • Выберите общую модель.
  • Отметьте нужные автоматические проверки. Можно воспользоваться «Выбрать все» или «Снять выбор».
  • При необходимости раскройте порядок выполнения проверок.
  • Нажмите «Запустить обработку».

Без выбранных пользовательских проверок данные всё равно сравниваются. Новые прогоны также формируют встроенную статистику бакетов.

«Сохранить настройки» сохраняет последовательность для повторного использования. При открытии сохранённой последовательности проверьте, что её датасет и профиль подходят текущей задаче.

Дополнительные настройки и код

Блок «Дополнительные настройки обработки» позволяет выбрать свои процедуры чтения, нормализации, сравнения и подготовки фактов. Для обычного анализа оставьте встроенные процедуры.

«Редактор проверок и процедур» предназначен для изменения Python-кода. Его использование требует понимания контракта входных и выходных данных. В доверенном локальном режиме Python исполняется с правами пользователя компьютера. Не вставляйте туда неизвестный код.

Журнал и время

Журнал показывает текущий этап, прогресс и ошибки. Длительности означают фактическое время обработки. Отдельно учитываются сравнение, сохранение и проверки; в новых результатах сохраняются дополнительные замеры чтения, разбора, нормализации и индексов.

«Отменить» останавливает активный запуск по правилам обработчика. «Повторить» создаёт повторную обработку. Если прогон завершился ошибкой, сначала прочитайте сообщение и исправьте входные данные или профиль.

7. Качество данных

Изучайте качество до сравнения долей отказов и изменений. Исключённые ответы не входят в базу валидных пар.

В таблице показаны данные BEFORE и AFTER: количество, знаменатель, процент и разница в процентных пунктах. Знаменатель — строки реестра соответствующей версии, включая ожидаемые отсутствующие ответы.

ПоказательЧто означаетЧто делать
Успешно прочитанОтвет прошёл этап чтенияМожно изучать дальнейшее сравнение
Ответ отсутствуетДля ожидаемой заявки нет ответа этой версииПроверить полноту выгрузки
Ошибка разбораПовреждённый или нечитаемый файлОткрыть исходник и исправить формат

Нажмите ненулевое число, чтобы открыть затронутые заявки. Сообщение «Проверка завершена без нарушений» — положительный результат проверки, а не отсутствие данных.

В старом прогоне некоторые новые поля могут отсутствовать. Для получения новой версии статистики выполните новый запуск. Если раздел не показывает результатов, проверьте выбранный прогон и его завершённость.

8. Обзор и карточка заявки

Обзор

Основные показатели:

  • Обнаружено заявок — в том числе неполные пары.
  • Валидных пар — база корректного сравнения.
  • С изменениями — заявки с изменившимися атрибутами.
  • Сменилось решение — заявки с разными итоговыми решениями.

Нажимайте на числа, чтобы перейти к списку. Блоки влияния и факторов изменения решения раскрываются отдельно. Они помогают найти связанные изменения, но не устанавливают причинность автоматически.

Карточка

  • Откройте список из отчёта.
  • Выберите заявку.
  • При необходимости снимите «Только изменения», чтобы увидеть и неизменившиеся поля.
  • Раскройте группу и конкретный атрибут.
  • Сравните «Было · MASTER» и «Стало · BETA».
  • Посмотрите путь и элемент массива: одинаковые подписи полей могут относиться к разным продуктам.
ТипЗначение
SAMEЗначение не изменилось по действующим правилам
VALUE_CHANGEDИзменилось сырое значение или тип
ATTRIBUTE_NEWАтрибут появился
ATTRIBUTE_LOSTАтрибут отсутствует в новой версии

Стрелка → означает переход «было → стало», а не увеличение. Например, 0.692 → 0.690 — уменьшение на 0.002. Зелёная подложка новой версии тоже не означает улучшение: она обозначает колонку AFTER.

Исходные документы

«Показать в исходных данных» переводит к исходникам. Путь выбранного поля отображается над ними; автоматическая точная прокрутка к этому полю внутри текста пока не реализована.

Подсветка строк:

  • жёлтый и ~ — изменённый участок;
  • зелёный и + — добавленные строки;
  • красный и − — удалённые строки.

Это текстовое сравнение: оно включает служебные поля и отличия оформления. Перестановка строк может выглядеть как удаление и добавление. Для очень большого изменённого участка подсветка может быть укрупнена. Аналитический тип изменения смотрите в сравнении атрибутов выше.

Внизу карточки можно сохранить заметку. Она привязывается к заявке и выбранному прогону. Закрыть карточку можно крестиком или Esc; при открытой заявке Esc сначала возвращает к списку.

9. Сводная таблица

Сводная помогает сравнивать группы атрибутов и значения.

  • Выберите разрез в «Строках»: например, продукт → партнёр → атрибут → значение.
  • Выберите «Колонки»: для простого сравнения подходит «Только срез».
  • Укажите число уровней.
  • При необходимости выберите «Только изменения».
  • Раскрывайте иерархию стрелками.
  • Нажимайте число для списка соответствующих заявок.

В ячейке считается число уникальных APP_ID. Одна заявка может входить в несколько групп, поэтому суммы всех ячеек не обязательно равны общему числу заявок.

Активные фильтры видны отдельными метками; их можно убрать. «Сбросить» возвращает базовую раскладку. «Сохранить раскладку» позволяет позднее открыть те же разрезы и фильтры.

Пагинация отображает часть фактов на странице. Кнопки CSV и JSON предназначены для выгрузки данных, а не только видимых строк. Если объём экспорта превышает ограничение сервера, сузьте фильтры.

10. Автоматические проверки

В разделе есть сопоставление проверок BEFORE/AFTER и подробный исходный отчёт.

Сопоставление

Выберите «Распределения и проверки» либо «Переходы между бакетами». Поиск работает по названию проверки, атрибуту и подписи бакета.

В сравнении сторон показаны число, база и процент. Последняя колонка — разница в процентных пунктах. Например, 75% → 50% означает −25 п. п., а не −25% относительного изменения.

«Нет результата» отличается от нуля. Ноль для отсутствующего бакета подставляется только тогда, когда успешный результат по соответствующему атрибуту на этой стороне существует.

Значения полей

ПолеСмысл
CNTДля бакетов — число строк атрибута; для пользовательской проверки — её заявленная мера
TOTALБаза расчёта конкретной проверки
METRICДоля; в сопоставлении показывается процентом
APP_IDSУникальные ID для раскрытия результата
SOURCEВерсия данных
ARGUMENTАтрибут, условие или описание бакета

Если одна заявка содержит несколько строк атрибута, CNT может быть больше количества уникальных APP_IDS. В подробном исходном отчёте METRIC может отображаться долей, например 0.25; это соответствует 25% в сравнительной таблице.

Распределения и переходы

BUCKET_DISTRIBUTION показывает распределение по каждому бакету отдельно для BEFORE и AFTER.

BUCKET_TRANSITION показывает только смену бакета. Его знаменатель включает все сопоставленные пары атрибута, в том числе оставшиеся в том же бакете. Поэтому сумма процентов переходов может быть меньше 100%.

Пример: из четырёх заявок только одна перешла A → B. Строка перехода содержит 1 / 4 = 25%. Остальные три не создают строки переходов, но входят в знаменатель.

Статусы проверок

  • PASS — проверка пройдена.
  • FAIL — обнаружено отклонение согласно условиям проверки.
  • ERROR — проверка не смогла выполниться.
  • INFO — статистическая строка, например распределение бакетов.

Нажмите результат с доступными APP_IDS, чтобы открыть список заявок. У пользовательских проверок список может быть ограничен примерами — интерфейс сообщает об этом. Встроенный бакетный отчёт сохраняет полный список уникальных ID, а список заявок открывается постранично.

11. Скоркарты, решения и фильтры

Исторические и расчётные решения

В панели «Решения, отказы и стоп-факторы · до / после» сначала выберите «Источник решений»:

  • Исторические решения — решения из исходных файлов.
  • Расчёт выбранного сценария — упрощённый расчёт по Score, порогу и стоп-факторам.

Сводки этой панели и матрица используют выбранный источник. Исторические решения в строках сохраняются для сравнения; расчётные показаны отдельно.

Фильтры

ФильтрКак применять
ПродуктОграничивает анализ выбранным продуктом
Score от / доГраницы включаются; пустое поле не ограничивает диапазон
СторонаДо, после, хотя бы одна сторона или обе стороны
Стоп-факторВсе, сработал, не сработал, неизвестно
Название стоп-фактораТекстовый поиск по сохранённым названиям
Причина отказаТекстовый поиск по исходной причине продукта
РешениеВсе, смена решения, отказ либо одобрение; отдельный выбор решения относится к AFTER
Ширина зоны порогаДопустимое абсолютное расстояние до порога, по умолчанию 0.1
Положение относительно порогаЛюбое, ниже, ровно на пороге либо выше

«Хотя бы одна сторона» означает, что набор условий выполняется хотя бы для BEFORE или AFTER. «Обе стороны» требует выполнения для каждой версии. Отсутствующий Score не считается нулём.

Чтобы искать рядом с порогом, задайте ширину и включите флажок «Около порога». Одного выбора «ниже» или «выше» без включения режима близости недостаточно. Для шкалы 0..100 задавайте ширину в тех же единицах, например 10.

После изменения фильтров проверяйте число результатов. «Сбросить фильтры» очищает критерии поиска; источник решений и настройки сценария выбираются отдельно.

Как читать статистику

Счётчики заявок используют уникальные APP_ID. Таблица и матрица переходов относятся к парам «заявка — продукт». Одна заявка с несколькими продуктами может присутствовать в нескольких строках и группах причин.

Раскройте «Переходы решений по текущей выборке» и нажмите переход, чтобы увидеть заявки. Аналогично открываются ненулевые группы причин отказа. В историческом режиме показываются исходные причины продукта; в сценарном — причина упрощённого расчёта.

Score и порог: почему больше не всегда лучше

Всегда проверяйте правило модели:

Правило одобренияScore 0.637 при пороге 0.55
Score ≥ порогаПорог пройден
Score ≤ порогаПорог не пройден

Если поле означает риск, высокий показатель может быть неблагоприятным. Если поле означает положительный балл, направление может быть обратным. Название Score само по себе направление не определяет.

В сценарной панели доступны также строгие правила > и <. При равенстве порогу ≥ и ≤ пропускают, а > и < — нет.

Блок «Стоп-факторы + скор» — отдельная диагностическая таблица со своим переключателем направления. Колонка «Ожидание» относится к этому выбранному правилу и не заменяет историческое решение СПР.

Скоркарта моделей

В таблице «Модель, продукт, балл и порог» агрегаты числа заявок и Score расположены колонками «до/после». Отсутствующее значение означает отсутствие соответствующей группы. По строке можно открыть заявки модели и продукта.

Секция предикторов показывает доступные поля модели. Универсальные вклады каждого признака в Score и SHAP отсутствуют в текущем наборе: приложение не вычисляет их из одних итоговых баллов.

12. Два режима стоп-фактора

Режимы находятся в панели анализа решений. Для отражения режима в её счётчиках выберите источник «Расчёт выбранного сценария».

Стоп-фактор сразу даёт отказ

Если стоп-фактор сработал, расчёт даёт отказ независимо от Score. При отсутствии стоп-фактора применяется выбранное правило порога. Неизвестные необходимые данные дают состояние «Неизвестно».

Стоп-фактор ухудшает Score

Задайте штраф за каждый сработавший стоп-фактор. Его величина берётся из выбранного профиля или из поля ввода.

При правиле «больше — лучше» штраф вычитается. При правиле «меньше — лучше» он прибавляется, чтобы ухудшать результат. Штраф применяется за каждый сработавший фактор.

Пример для правила Score ≥ 0.60:

ДанныеЖёсткий режимРежим штрафа
Score 0.85, один стоп-фактор, штраф 0.10ОтказИтоговый Score 0.75, одобрение
Score 0.85, один стоп-фактор, штраф 0.30ОтказИтоговый Score 0.55, отказ

Результат этого расчёта не записывается обратно в исходный ответ. Другие банковские правила и выдача предложений полностью не воспроизводятся.

Старые прогоны без количества стоп-факторов требуют повторного запуска. Не интерпретируйте отсутствие количества как ноль.

Общие фильтры и сценарий применяются к обзору, качеству, сводной, бакетам, скоркартам и детализации. Сохранённые проверки показывают исходный результат полного прогона. Отдельная симуляция порога одного продукта имеет свои настройки.

13. Сценарий изменения порога

Раздел «Сценарии» отвечает на вопрос: «Что изменится, если поменять порог одного продукта?»

  • Выберите готовый прогон.
  • Откройте «Сценарии».
  • Укажите ID продукта.
  • Задайте новый порог в поддерживаемом диапазоне 0..1.
  • Выберите условие одобрения: ≥ или ≤.
  • Нажмите «Рассчитать сценарий».
  • Изучите число изменившихся решений и список заявок.

В этом разделе используются данные AFTER и жёсткое правило стоп-фактора. Это отдельная упрощённая симуляция, а не тот же переключатель штрафов из панели скоркарт.

Сценарий сохраняется с базовым прогоном. Чтобы открыть сохранённый результат, выберите именно его базовый прогон. Заявки с недостаточными данными могут быть исключены из расчёта; их количество отображается отдельно.

14. Экспорт, история и доступ

Экспорт

  • На обзоре готового прогона нажмите «Скачать Excel», «Скачать HTML» или «Скачать XML».
  • В Excel лист «Сводная таблица» пересчитывается по листу «Исходные данные». В крупной выгрузке сохраняйте порядок и группы исходных строк.
  • HTML включает обзор, заявки и детали изменений. Его можно открыть без интернета.
  • В XML проверки PASS и FAIL отделены от статистики бакетов. CSV и JSON с фактами доступны в расширенной сводной.
  • Отчёты учитывают текущую выборку и сценарий. Сохранённые результаты проверок относятся к полному прогону.

Ссылки в HTML возвращают к приложению. На другом компьютере для их работы нужен доступ к адресу приложения; локальный адрес 127.0.0.1 указывает на компьютер получателя, а не на ваш сервер.

История

«История и доступ» содержит журнал действий проекта. Он доступен ведущему аналитику и администратору. Используйте его, чтобы проверить, кто и когда выполнял действия.

Пользователи

Администратор открывает «Пользователи», выбирает пользователя и назначает роль в нужном проекте. Регистрация сама по себе прав на проект не выдаёт.

Пул и исполнение

Раздел для ведущего аналитика позволяет подготовить пул заявок и получить два среза по демонстрационным правилам либо через настроенное HTTP-подключение СПР. Это инструмент формирования данных. Для анализа уже готовых ответов используйте обычную загрузку в «Данных и профилях».

16. Практические маршруты

Найти новые отказы

  • Выберите готовый прогон и проверьте качество.
  • Откройте скоркарты и источник «Исторические решения».
  • Выберите продукт при необходимости.
  • Раскройте переходы решений.
  • Нажмите APPROVE → REJECT.
  • Откройте заявку, сравните решение, Score, порог, стоп-факторы и исходники.
  • Запишите подтверждённое наблюдение в заметку; гипотезу о причине обозначьте как гипотезу.

Найти заявки около порога

  • Выберите сторону, например AFTER.
  • Укажите продукт и ширину зоны, например 0.1 для шкалы 0..1.
  • Включите «Около порога».
  • При необходимости выберите «ниже», «ровно» или «выше».
  • Смотрите Score, конкретный порог этой заявки и подписанное отклонение.
  • Сопоставьте историческое решение с расчётным правилом, а затем откройте интересующую заявку.

Проверить изменение распределения Score

  • Убедитесь, что путь Score задан в профиле и профиль общий для двух версий.
  • Выполните новый прогон.
  • В проверках выберите «Распределения и проверки».
  • Найдите путь Score поиском.
  • Сравните проценты BEFORE/AFTER и разницу в п. п.
  • Переключитесь на переходы между бакетами.
  • Откройте заявки нужного перехода и проверьте сырые значения.

Передать результаты коллеге

  • Зафиксируйте ID прогона и базу валидных пар.
  • Укажите, используются исторические решения или сценарий.
  • Запишите направление порога, штраф и фильтры.
  • Сохраните заметки к ключевым заявкам.
  • Экспортируйте нужный отчёт и проверьте, какие фильтры он учитывает.
  • Добавьте ограничения качества данных и неподтверждённые предположения.

Технические контракты находятся в docs/procedure-contracts.md, права — в docs/roles-and-modules.md, текущие незавершённые пункты разработки — в docs/prompt2-status.md.
