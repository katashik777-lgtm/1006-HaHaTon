## Как проверять на защите

Отдаёте команде папку `HOLDOUT/RUN-20260827-0001-HOLDOUT` и просите прогнать. Правильный результат: **248 заявок с различиями, у 186 сменилось решение**.

| Ответ команды | Что это значит |
|---|---|
| **248** | Считают правильно |
| **998** или близко | Не исключили технические поля `appData.request_id` и `appData.createDateTime` — они отличаются у всех заявок |
| Заметно больше 248 | Массивы сравниваются по позиции, а не по ключу элемента |
| Заметно меньше 248 | Потерян сценарий. Чаще всего неверно обработан массив-вектор `decisionResult.scoring[].value` — там сравнивать надо как раз по индексу |

Второе число для сверки — 186 заявок со сменой решения.

## Три ловушки, заложенные в данные

1. **Два технических поля** отличаются у каждой заявки. Их надо исключать, и список должен быть настройкой, а не константой в коде.
2. **Восемь из девяти массивов** сопоставляются по ключу элемента, а не по позиции. У двух ключ составной: `available_offers[]` — `product_id` + `type`, справочники — `mfo_id` + `product_id`.
3. **Девятый массив** `decisionResult.scoring[].value` — наоборот: это вектор, позиция значима, ключ — индекс. Автоматически отличить его от обычного массива скаляров нельзя.

Плюс более тонкая: ключ строки витрины обязан включать `modelName`, иначе предикторы разных моделей склеиваются.

## Про скорость

Наивная однопоточная реализация на Python проходит открытый датасет за **4.6 секунды** (чтение 0.5 · приведение 2.3 · сравнение 1.1 · проверки 0.6 · сводная 0.1). То есть согласованная планка приёмки «приведение до 5 минут» практически бесплатная — она отсекает только нерабочее.

Различать команды будет не батч, а отклик отчёта поверх 290 тысяч строк, поведение под двумя пользователями и наблюдаемость долгого этапа.

Демонстрируют на своём железе, поэтому абсолютные секунды между командами несравнимы: оценивайте объяснение — что профилировали, где узкое место, что дало ускорение, названа ли конфигурация машины.

## Что можно показывать студентам

Можно показывать карточку задания, `examples/`, Excel-демо и браузерный прототип. Сразу проговорите: это учебные примеры, не готовое решение и не обязательный UI. Сценарий вводной встречи — в `03_ИНСТРУКЦИЯ_ПРЕЗЕНТАЦИИ_СТУДЕНТАМ.md`.

## Чего участникам не показываем

- Папку `HOLDOUT/`, любой из трёх файлов `ЭТАЛОН/` и правильные контрольные числа.
- Реализации разбора и сравнения, baseline-скрипт и генератор датасета.
- Внутренние комментарии к проверке команд.


### Проверка качества проекта
Оценка работы должна опираться на воспроизводимые тесты и фактические результаты, независимо от того, выполняет проверку человек или нейросеть. Изменения аналитики описаны в `docs/analytics-improvements.md` в корне репозитория.
